      About

      Synthetic data

      The match, both teams and every player are made up. A script generated about 700 events with a fixed seed, so it is the same match every time. It is not real Premier League data.

      How it works

      1. Code computes the facts. Plain Python scores every pass and carry with a simple Expected Threat (xT) grid, finds the key moments and counts the stats. No model touches a number.
      2. A model words them. Three agents on Microsoft Foundry (Analyst, Narrator, Personalizer) turn those facts into sentences for each reader.
      3. Every sentence is checked. Code checks each name and number against the data and blocks wording the facts can't support, such as how a shot looked or what the score did later. Text that fails is retried or fixed by hand, and re-checked.

      Honest limits

      • The xT grid is a simple distance-to-goal model, not one trained on real matches.
      • The checks catch known ways of inventing facts. They can't prove every sentence is perfect.
      • All text was generated before you opened the page; nothing is written live.
      • Some texts were edited by hand while proofreading. Edited texts pass the same checks.
      • A "spell on top" moment covers a stretch of play, so it appears when that stretch ends.
      • Arabic is planned but not written yet.
